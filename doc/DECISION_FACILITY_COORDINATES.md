# 決定記録: 医療機関の座標をどこから取るか

ステータス: **決定済み（2026-08-05）。決定2（医療情報ネットの公表座標の統合）も
2026-08-05（M13）に「保留」から「GO・実施済み」へ更新した**（詳細は「決定2の実施
（2026-08-05・M13）」節）。
対象: `R7/001723127.xlsx`（構想区域別の医療機関個票、11,760施設）の地図表示

このファイルは手で維持する（生成物ではない）。関連する実測レポートは
`doc/FACILITY_LINKAGE.md`（名寄せ）と `doc/FACILITY_GEO_AUDIT.md`（検算）で、こちらは生成物。

## 背景

要件 `doc/REQUIREMENTS.md` §7 に、未決事項としてこう書いてあった:

> 名称突合の未マッチ率が高い場合、住所ジオコーディング（医療情報ネット＋国土地理院 API）への
> 切替を第2弾で検討（第2弾）。

M5 時点の実測は、`ksj/P04-20`（国土数値情報 医療機関データ、令和2年度）との名寄せで
**11,760件中10,244件（87.1%）に座標を付与**、残り1,516件は座標なし（`doc/FACILITY_LINKAGE.md`）。
この 87.1% を「未マッチ率が高い」と評価するかが未決だった。

## 決定1: 住所ジオコーディングはやらない（No-Go）

### 理由

1. **原典が住所を持たない。** `facility_basic.csv` の所在地は市区町村までで、番地が無い
   （列は `pref_code, pref_name, area_code, area_name, record_id, source_sheet, source_row,
   facility_seq, facility_name, municipality`）。ジオコーディングの入力となる住所文字列を得るには
   第3のデータセットが要り、**そのデータセットと個票を結び付ける作業は、いまP04でやっているのと
   同じ名寄せ問題**である（医療機関に恒久IDが無いため）。問題は消えず、移動するだけになる。
2. **出力が推定値になる。** 住所文字列からの座標生成は定義上「位置の推定」であり、
   要件 §4.3 の「**位置の推測はしない**」に正面から反する。出所ラベルや「推定」バッジを
   付けても、この明文の違反は解消しない。
3. **費用対効果が低い。** 未付与1,516件は一覧には全項目とともに出ており、
   **情報が欠落しているのではなく地図の点にならないだけ**である。回収して増えるのは
   「地図から探せる施設の数」だけで、21指標の情報量は増えない。

### 結果として受け入れる制約

- 地図の点は「**所在地を確認できた施設の部分集合**」であり、施設の完全な分布図ではない。
- したがって、**点の密度による都道府県間・区域間の比較は、この可視化サイトの用途に含めない**。
  施設数・病床数の集計は必ず全件データ（一覧・CSV）から行う。
- この前提を利用者に伝えるため、区域パネルに座標カバレッジを常設表示する（決定4）。

## 決定2: 公表座標の統合は保留（実測済み・再検討可能）

住所ジオコーディングとは別に、**医療情報ネット（医療機能情報提供制度）が施設ごとの
公表座標そのものを持っている**ことが分かった（`iryojoho/`、`doc/DATA_SOURCES.md`）。
これは推定値ではなく厚労省の公表値なので、決定1の理由2は当てはまらない。

### 実測（2025-06-01時点のデータで測定）

| 項目 | 実測値 |
|---|---|
| 参照側の収録件数 | 病院 7,587件・診療所 75,254件 |
| うち使える座標 | 78,385件（5.4%が `0.0`/`0.0` のセンチネル） |
| 未付与1,516件のうち、同一都道府県内で正規化名が完全一致し市区町村も整合して**一意に決まる**もの | **830件**（うち72件は原典の所在地欄が空で市区町村を検証できないもの） |
| 統合した場合の座標付与率 | 87.1% → **94.2%**（市区町村を検証できた758件だけなら93.5%） |

参照側は P04 に無い **都道府県コード・市区町村コード**を持ち、住所も都道府県名から始まる
完全な形なので、P04 で必要だった点-多角形判定による同名市区町村の切り分けが要らない。
公表時点も R7 と同じ年度内に揃えられる（P04 は令和2年度で5年の開きがある）。

### 保留する理由

**統合は要件 §4.3 の改定を伴う。** §4.3 は現在「未マッチ施設は地図ポイントなし・一覧表のみで表示
（位置の推測はしない）」と書いており、この文言のままでは未マッチ施設に点を与えられない。
「住所から生成した推定座標は禁止／別の公表物の公表座標は厳格な同一性確認の後に利用可」へ
改める判断は、実装の細部ではなく**要件の変更**であり、独立した決定として扱う。

### 統合する場合に満たすべき条件（先に決めておく）

1. 医療情報ネットの原ファイルを不変の生データとして保存し、SHA-256 を記録する（**実施済み**）。
2. 公表時点を R7 個票にできるだけ合わせる（**2025-06-01 を採用済み**）。
3. 名称・都道府県・市区町村・一意性を複合で確認し、一つでも欠ければ採用しない。
4. 座標の出所（P04 由来か医療情報ネット由来か）を施設ごとに保持し、画面と CSV で区別できるようにする。
5. `0.0`/`0.0` のセンチネルを日本の緯度経度の範囲で除外する（空欄判定では検出できない）。
6. 要件 §4.3 を改定し、その改定自体を本ファイルに記録する。

### 越えてはならない一線（統合する／しないに関わらず）

- 医療情報ネットの**住所を API に入力した結果**を、施設の公表座標として扱わない。
- ジオコーディング API の検索順位・信頼度スコアを、施設同一性の根拠にしない。
- 一意に同定できない同名施設を、「近いから」「区域内だから」という理由だけで採用しない。
- 推定点と公表点を区別せずに同じレイヤへ載せない。
- 回収率の目標を達成するために採用条件を緩めない。
- 市区町村の重心・住所の代表点・郵便番号の中心を施設の位置として表示しない。
- **出典が正しいことと、座標が現実に正しいことを同一視しない**（下記の76件がその実例）。

## 決定3: 検算で否定された座標は地図に出さない

医療情報ネットの公表座標を**参照**として、付与済み10,244件を検算した（`doc/FACILITY_GEO_AUDIT.md`）。

| 結果 | 件数 |
|---|---|
| 100m未満で一致（`agree`） | 7,377 |
| 100m以上1km未満（`minor_gap`） | 446 |
| **1km以上離れている（`conflict`）** | **76** |
| 参照側で一意に確認できず検算できない（`no_reference`） | 2,345 |

距離の中央値は13m、90%点は65m、99%点は977m。**P04由来の座標は大半が今も妥当**である一方、
76件は2つの公表物が1km以上離れた位置を示している（最大32km）。この76件は2種類に分かれる:

- **住所は実質同一なのに座標だけが離れている**（例: 産科・婦人科久米クリニックは双方とも
  「いちき串木野市曙町」だが約32km離れている）→ 移転ではなく、いずれかの座標そのものが誤っている。
- **住所自体が異なる**（例: 峯苫医院はP04「八代市坂本町坂本」対 参照「八代市渡町」）→ 移転と解釈できる。

いずれにせよ**いま地図に出ている点が現在の所在地を指している保証は無い**。
本リポジトリの原則は「**誤って別の場所の座標を採用することは、座標が無いことよりも悪い**」
（`doc/FACILITY_LINKAGE.md`）なので:

- **値は補正しない**（参照側の座標を採用することは決定2＝保留中の統合に当たる）。
- **表示用データセット（`area_facilities_R7.json`）ではこの76件の座標を出力しない**。
  一覧には21指標すべてとともに残し、「地図に表示なし（座標が不一致）」と理由を示す。
- 正本 `facility_geo_linkage.csv` は書き換えない（P04名寄せの結果そのものとして保つ）。
  取り下げは下流（`tools/build_web_facilities.py`）で行う。
- 原典側の欠陥として `known_issues` に記録し、画面の「データの既知の問題」へ流す
  （`facility_coordinate_conflicts_with_published_reference`）。

## 決定4: 座標カバレッジを常設表示する

都道府県別の座標付与率は 60.1%（長崎県）〜96.9%（福井県）と幅がある。
点の数をそのまま施設数と読むと「この県には医療機関が少ない」という誤った印象を与える。
区域パネルの医療機関一覧に「**地図に表示：M件 / この区域のN件**」を常設し、
出ていない分の内訳（名寄せで特定できず／座標が不一致）を添える。

## 決定2の実施（2026-08-05・M13）

決定2（上記「決定2: 公表座標の統合は保留」）を**GO**とし、実施した。ユーザーの判断による。
決定2・決定3の本文（上記）はそのまま履歴として残し、書き換えていない。実施内容は本節に記録する。

### (a) 決定の内容

「保留」としていた医療情報ネットの公表座標の統合を実施した。P04名寄せを優先し、それで位置が
定まらない施設に限り、医療情報ネットの公表座標を名称・都道府県・市区町村・一意性の複合確認が
できた場合のみ座標源として採用する。

### (b) 要件 §4.3 の改定

`doc/REQUIREMENTS.md` §4.3「医療機関の位置」を、以下の文言に改定した（改定前は「国土数値情報
『医療機関データ』と施設名・所在区域で名称突合。未マッチ率をレポートし、未マッチ施設は地図
ポイントなし・一覧表のみで表示(位置の推測はしない)」のみだった）:

> 国土数値情報「医療機関データ」(P04)と施設名・所在区域で名称突合する。P04で位置が定まらない
> 施設については、**別の公表物が公表している座標**（医療情報ネット）に限り、名称・都道府県・
> 市区町村・一意性を複合で確認できた場合のみ採用する。**住所等から生成した推定座標（ジオコー
> ディング結果）は用いない。** 採用した座標は出所を施設ごとに保持し、画面とCSVで区別できるように
> する。いずれの方法でも位置が定まらない施設、および複数の公表物が食い違う施設は、地図ポイント
> なし・一覧表のみで表示する（位置の推測はしない）。未マッチ率と出所の内訳はレポートに残す。

### (c) 確定した数字と、94.2%見積もりとの差

| 項目 | 件数 |
|---|---:|
| 医療機関の総数 | 11,760 |
| P04名寄せが座標を与えた数（従来どおり） | 10,244 |
| うち検算で否定され座標を出さない数（従来どおり、決定3） | 76 |
| P04由来で地図に出る数 | 10,168 |
| 医療情報ネットの公表座標を採用した数（M13で追加） | 758 |
| **地図に出る座標の合計** | **10,926（11,760件中92.9%）** |
| 採用しなかった数（市区町村を検証できず） | 72 |
| 採用しなかった数（一意に同定できず） | 686 |

決定2の文書は「830件回収で 87.1%→94.2%」と見積もっていた。実際は92.9%で、差は76件（検算で
否定され取り下げた分、決定3）＋72件（市区町村を検証できない分、下記(d)）＝**148件**による
（76+72=148）。94.2%は取り下げ前・採用条件を厳密に当てはめる前の見積もりだった。

### (d) 採用しなかった72件の理由

原典（病床機能報告）が未報告で、`facility_basic.csv` の所在地欄自体が空である施設は、市区町村
を検証できない。決定2の採用条件3「名称・都道府県・市区町村・一意性を複合で確認し、一つでも欠け
れば採用しない」を満たせないため、この72件は採用しなかった（`facility_geo_audit.csv` の
`reference_status=='unique_municipality_unverified'`）。残り686件（`none`/`municipality_mismatch`/
`ambiguous`）は一意に同定できないため、従来どおり採用していない。

### (e) 12件の区域食い違いを棄却理由としなかった理由

採用した758件のうち12件は、参照座標の点-多角形判定が原典（`facility_basic.csv`）の記載区域と
食い違う（9件は別の構想区域のポリゴンに落ち、3件はどの区域ポリゴンにも属さない）。これは棄却
理由ではなく**観測事実**として記録した。名称・市区町村までの一致は確認済みであり、区域判定の
食い違いは境界ポリゴン（`area_boundaries_R7.geojson`、簡略化・海岸線・境界近傍の誤差を持つ）
側の問題であって、施設同一性を否定する材料ではないため、この12件も座標を出す対象に含めている。

### (f) 決定3（76件の取り下げ）は結論を維持するが、理由が変わった

決定3の元の理由は「参照側の座標を採用することは決定2＝保留中の統合に当たる」だった。決定2が
GOになった今、**この理由は失効している**。**新しい理由は「2つの公表物が食い違っており、どちら
が正しいか公表物からは決められないため」**（ユーザーの判断）。結論（この76件はこの可視化サイト
では地図に出さない）自体は変わっていない。

### 決定4の数字について（M13以前の実測）

決定4に載っている都道府県別の座標付与率（60.1%〜96.9%）は**P04名寄せのみの時点（M13以前）の
実測**であり、M13で座標源が2系統になった現在のカバレッジを表さない。数字自体は書き換えず、
再計算もしていない。

## 再検討の条件

**2026-08-05更新**: 決定2は上記「決定2の実施」でGOとし、実施済みになった（1つ目の条件が
実際に起きたことになる）。以下は保留期間中に定めていた再検討条件の記録として、履歴のまま
残す（今後さらに座標源を追加する・現行の採用条件を見直す、といった判断が要る場合の参考に
なりうるため）。

次のいずれかが起きたら決定2を再検討する:

- 要件 §4.3 を改定する判断が下りたとき。
- サイトの主目的が「近隣施設の検索」や「アクセス分析」へ変わったとき
  （そのときは点の網羅性が機能要件になる）。
- 公的な恒久施設IDが提供され、年度をまたぐ名寄せが不要になったとき。
- 利用者から、地図の欠測が重大な利用障害であるという指摘を受けたとき。

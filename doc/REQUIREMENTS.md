# 要件定義書 — 2040年に向けた地域医療構想 可視化サイト

作成日: 2026-08-04 / ステータス: 合意済み(実装前)

## 1. 目的・背景

厚生労働省「2040年に向けた地域医療構想」の公開データ(病床機能報告・医療需要推計)を、
**データの真正性(出典・非改変)を担保した形で**可視化し、誰でも地域の医療の現状を
把握できるようにする。公的統計であり二次利用上の制約は小さい。

- 主用途: 地域の現状把握(RESAS のような地図中心の閲覧体験)
- 副用途: 加工済みデータの CSV ダウンロード(再分析用)

## 2. 配信形態

| 項目 | 決定内容 |
|---|---|
| ホスティング | GitHub Pages(静的サイト、サーバーレス) |
| リポジトリ | パブリック。生データ(R6/R7 の Excel)も出典・SHA-256 付きで公開 |
| ビルド/デプロイ | GitHub Actions(push → ビルド → Pages 配信) |

## 3. 機能要件

### 3.1 地図表示(3階層)

| 階層 | 表示 | 備考 |
|---|---|---|
| 都道府県 | コロプレス(47都道府県+全国) | 001722915(R7)ベース。概観用 |
| 構想区域(二次医療圏) | コロプレス(339区域) | 001723349(R7)ベース。主役の表示単位 |
| 医療機関 | ポイント表示 | 001723127(R7)ベース。位置情報は外部突合(§4.3) |

- ズーム/選択に応じて 都道府県 → 構想区域 → 医療機関 とドリルダウンできること。
- 区域クリックで詳細パネル(指標の内訳・区域内医療機関の一覧表)を表示。

### 3.2 可視化する指標(初期リリース)

1. **病床機能別の病床数 vs 将来必要量**
   - 高度急性期/急性期/回復期/慢性期の現状報告と必要量の比較。
   - ⚠ 病床機能報告の集計値と「将来の必要量」は計算方法が異なる。厚労省の注記に
     従い、併記箇所には必ず注意書きを表示する(機能要件として必須)。
2. **在宅(訪問診療)・外来の医療需要推計(2024→2050年度)**
   - 001728462 ベース。年度スライダーによる時系列表示。
3. **医療機関別の病床数・診療実績・医師数**
   - 区域選択時のドリルダウン一覧表+地図ポイント。

**実装済み(M9・M12)**: 構想区域レベルの2指標(見込量比(2025年)・実績の1年変化(2024→2025))に限り、R6→R7の年度間比較を追加した(`data/processed/area_yoy_R6_R7.json`)。都道府県レベルも同じ2指標をM12で追加した(`data/processed/prefecture_yoy_R6_R7.json`)。都道府県レベルで対象外なのは「2024年実績どうしの比較」のみ(下記§7参照。R6/R7で完全一致するため)。

### 3.3 CSV ダウンロード(両方式)

1. **表示条件絞り込み CSV**: 現在の選択(区域・指標・年度)を反映した CSV を
   クライアント側で生成しダウンロード。
2. **加工済みデータセット一括 DL**: tidy 形式の全加工データを一括配布。
   由来メタデータ(出典 URL・公表年度・取得日・元ファイルの SHA-256)を同梱する。

## 4. データ要件

### 4.1 真正性(CLAUDE.md のルールを継承)

- `R6/`・`R7/` の生データは編集禁止。加工結果は `data/processed/` へ出力。
- 出典は `DATA_SOURCES.md`、ハッシュは `SHA256SUMS` で管理。
- CI(GitHub Actions)で `sha256sum -c SHA256SUMS` を実行し、生データの
  非改変をビルドごとに検証する。

### 4.2 加工パイプライン

- Python 3.11 + openpyxl。帳票レイアウト(結合セル・繰り返しブロック)は
  位置ベースで抽出。
- 正規化ルール:
  - 構想区域コード: 数値 `101` ⇔ ゼロ埋め文字列 `"0101"` を統一キーに正規化。
  - 人口単位: 「万人」表記と実数の混在を実数に統一し、変換元単位を列で保持。

### 4.3 地理データ(外部ソースとの突合)

| 対象 | 方針 |
|---|---|
| 構想区域の境界 | 国土数値情報「二次医療圏」を代用。区割が構想区域と異なる県は市区町村境界から合成して手動補正。突合結果(一致/補正/根拠)を検証レポートとして残す |
| 医療機関の位置 | 国土数値情報「医療機関データ」(P04)と施設名・所在区域で名称突合する。P04で位置が定まらない施設については、**別の公表物が公表している座標**(医療情報ネット)に限り、名称・都道府県・市区町村・一意性を複合で確認できた場合のみ採用する。**住所等から生成した推定座標(ジオコーディング結果)は用いない。** 採用した座標は出所を施設ごとに保持し、画面とCSVで区別できるようにする。いずれの方法でも位置が定まらない施設、および複数の公表物が食い違う施設は、地図ポイントなし・一覧表のみで表示する(位置の推測はしない)。未マッチ率と出所の内訳はレポートに残す |

※ 「医療機関の位置」の方針は2026-08-05(M13)に改定した。改定前は「国土数値情報との名称突合のみ、未マッチ施設は地図ポイントなし」だった。改定の判断材料・検討経緯・満たすべき条件との対応は `doc/DECISION_FACILITY_COORDINATES.md` を参照。

外部地理データも `DATA_SOURCES.md` / `SHA256SUMS` に追記して同ルールで管理する。

## 5. 技術構成

| レイヤ | 選定 |
|---|---|
| フロントエンド | Vite + React + MapLibre GL JS |
| 地図データ | ベクトルタイル(背景)+ GeoJSON(区域境界・施設ポイント) |
| データ配信 | ビルド時に静的 JSON/CSV を生成。区域別詳細(339区域)は遅延読み込みで初期ロードを軽量化 |
| 前処理 | Python 3.11 + openpyxl(既存環境) |

## 6. 非機能要件

- **出典表示**: すべての可視化に厚労省ページ URL・公表年度を表示できること。
- **注記の担保**: 病床数と必要量の併記時は比較上の注意書きを常時表示。
- **性能**: 初期表示は全国コロプレスのみ読み込み。施設・区域詳細はオンデマンド取得。
- **再現性**: 生データ取得〜加工〜デプロイまでの手順をリポジトリ内で完結・自動化。
- **環境**: Windows 開発環境・日本語ファイル名。Python 実行時は
  `PYTHONIOENCODING=utf-8` を付与。

  確認できた758件を座標源として採用した(採用しなかったのは、市区町村を検証できない72件と、
  一意に同定できない686件)。地図に出る座標は 10,244件(P04由来)−76件(検算で否定・下記)+758件

  検算で否定され座標を出さない76件と、市区町村を検証できず採用しなかった72件の合計148件による

  対応・再検討条件は `doc/DECISION_FACILITY_COORDINATES.md`。付与済み座標の検算(76件が別の公表物と
  1km以上食い違う)は `doc/FACILITY_GEO_AUDIT.md`。
